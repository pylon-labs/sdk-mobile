# Pylon Chat SDK for Flutter

Add Pylon's chat widget to your Flutter app to enable in-app customer support.

## Requirements

- Flutter >= 3.22
- iOS >= 13.0
- Android minSdkVersion >= 24

---

## Installation

This SDK is distributed as source code and installed from a local directory.

### Step 1: Clone the Repository

Clone the SDK repository anywhere on your machine, but preferably forked into your own repository:

```bash
git clone https://github.com/pylon-labs/sdk-mobile.git
```

### Step 2: Add the Package

Point your app's `pubspec.yaml` at the `flutter` directory:

```yaml
dependencies:
  pylon_chat:
    path: /path/to/sdk-mobile/flutter
```

Then:

```bash
flutter pub get
```

iOS linking happens automatically on the next build (`pod install` runs as part of it). Android auto-links with no action needed.

### Step 3: Get Your Pylon App ID

1. Login to [app.usepylon.com](https://app.usepylon.com)
2. Go to Settings → Chat Widget
3. Copy your App ID

## Quick Start

`PylonChatView` is an overlay. It fills whatever space you give it, but only the chat bubble is actually there — everything else lets touches through to your app. So put it last in a full-screen `Stack`:

```dart
import 'package:flutter/material.dart';
import 'package:pylon_chat/pylon_chat.dart';

class HomePage extends StatelessWidget {
  const HomePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Stack(
      children: <Widget>[
        const MyAppContent(),
        PylonChatView(
          config: const PylonConfig(appId: 'YOUR_APP_ID'),
          user: const PylonUser(
            email: 'user@example.com',
            name: 'User Name',
          ),
        ),
      ],
    );
  }
}
```

### Putting it above every route

Most apps want one bubble that stays put as the user navigates. Mount it in `MaterialApp.builder`, which sits above the `Navigator`:

```dart
MaterialApp(
  home: const HomePage(),
  builder: (BuildContext context, Widget? child) {
    return Stack(
      children: <Widget>[
        if (child != null) child,
        Positioned.fill(
          child: PylonChatView(config: config, user: user),
        ),
      ],
    );
  },
)
```

This is the recommended setup. Besides surviving route changes, it keeps the widget out of any `Scaffold` that resizes for the keyboard — the SDK does its own keyboard handling, and two layers of it fight each other.

### Identity Verification (Strongly Recommended)

We strongly recommend setting up [Identity Verification](https://docs.usepylon.com/pylon-docs/chat-widget/identity-verification). The `emailHash` needs to be generated by the server responsible for authorizing your mobile app — never in the app itself, since shipping the signing secret to a mobile binary defeats the point.

```dart
PylonUser(
  email: 'user@example.com',
  name: 'User Name',
  emailHash: 'hash_generated_by_your_server',
)
```

## API Reference

### `PylonChatView`

| Parameter | Type | Description |
| --- | --- | --- |
| `config` | `PylonConfig` | Required. See below. |
| `user` | `PylonUser?` | The visitor. Null runs the widget anonymously and collects an email in the chat. |
| `controller` | `PylonChatController?` | Drives the widget imperatively. |
| `passthroughTouches` | `bool` | Defaults to true. See [Touch pass-through](#touch-pass-through). |
| `onLoaded` | `VoidCallback?` | The web view finished loading. |
| `onInitialized` | `VoidCallback?` | The widget was initialised with your config and user. |
| `onReady` | `VoidCallback?` | The widget's own scripts are ready. |
| `onChatOpened` | `VoidCallback?` | The chat window expanded. |
| `onChatClosed` | `void Function(bool wasOpen)?` | The chat window collapsed. |
| `onUnreadCountChanged` | `void Function(int count)?` | The unread count changed. |
| `onMessageReceived` | `void Function(String message)?` | A message arrived. |
| `onError` | `void Function(String error)?` | The widget failed to load. |

### `PylonConfig`

```dart
PylonConfig(
  appId: 'YOUR_APP_ID',        // required
  enableLogging: true,          // SDK + widget console output to the platform log
  debugMode: false,             // draws the SDK's hit test regions over the widget
  primaryColor: '#5B4CF5',      // CSS colour string
  widgetBaseUrl: null,          // defaults to https://widget.usepylon.com
  widgetScriptUrl: null,        // defaults to <default base>/widget/<appId>
)
```

> **Note:** `widgetScriptUrl` defaults from the *production* host, not from `widgetBaseUrl`. If you point `widgetBaseUrl` at a local server, set `widgetScriptUrl` too. This matches the iOS and Android SDKs.

### `PylonUser`

```dart
PylonUser(
  email: 'user@example.com',   // required
  name: 'User Name',            // required
  avatarUrl: null,
  emailHash: null,              // identity verification, generated server-side
  accountId: null,              // the Pylon account this user belongs to
  accountExternalId: null,      // the account's ID in your own system
)
```

### `PylonChatController`

Create one, hand it to the widget, and call methods on it. Calls made before the widget mounts are buffered and replayed, so there is no "ready" callback to wait for.

```dart
class _MyPageState extends State<MyPage> {
  final PylonChatController _pylon = PylonChatController();

  @override
  void dispose() {
    _pylon.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Stack(
      children: <Widget>[
        MyContent(onHelpTap: _pylon.openChat),
        PylonChatView(config: config, user: user, controller: _pylon),
      ],
    );
  }
}
```

| Method | Description |
| --- | --- |
| `openChat()` / `closeChat()` | Expand or collapse the chat window. |
| `showChatBubble()` / `hideChatBubble()` | Show or hide the bubble. Hiding it does not disable the chat — `openChat()` still works, which is how you drive it from your own UI. |
| `showNewMessage(String, {bool isHtml})` | Open the chat with a message pre-filled. |
| `setNewIssueCustomFields(Map<String, Object?>)` | Custom fields for issues created from this session. Null values are dropped. |
| `setTicketFormFields(Map<String, Object?>)` | Pre-fill the ticket form. |
| `showTicketForm(String slug)` | Open a ticket form. |
| `showKnowledgeBaseArticle(String articleId)` | Open a knowledge base article. |
| `updateUser(PylonUser)` | Replace the identified user. |
| `setEmailHash(String?)` | Update the identity verification hash. |
| `refreshInteractiveBounds()` | Re-query where the widget's tap targets are. Rarely needed. |

It also exposes two `ValueListenable`s, so your own chrome can react without extra state:

```dart
ValueListenableBuilder<int>(
  valueListenable: _pylon.unreadCount,
  builder: (BuildContext context, int count, _) => Badge(
    isLabelVisible: count > 0,
    label: Text('$count'),
    child: const Icon(Icons.forum_outlined),
  ),
)
```

`_pylon.isChatOpen` works the same way — useful for hiding your own FAB while the chat is up.

## Usage Patterns

### Reacting to events

```dart
PylonChatView(
  config: config,
  user: user,
  onChatOpened: () => analytics.log('support_chat_opened'),
  onChatClosed: (bool wasOpen) => analytics.log('support_chat_closed'),
  onUnreadCountChanged: (int count) => setState(() => _unread = count),
  onError: (String error) => debugPrint('Pylon: $error'),
)
```

### Login and logout

Switching to a different person should start a clean session. Give the widget a `key` derived from the user so Flutter rebuilds it:

```dart
PylonChatView(
  key: ValueKey<String?>(currentUser?.email),
  config: config,
  user: currentUser,  // null when signed out
)
```

Changes that are *not* an identity switch — an `emailHash` arriving after login, a display name edit — are applied in place with no rebuild.

### Custom fields

```dart
_pylon.setNewIssueCustomFields(<String, Object?>{
  'source': 'mobile-app',
  'app_version': packageInfo.version,
  'platform': Theme.of(context).platform.name,
});
```

### Your own support button

```dart
// Hide Pylon's bubble and use your own entry point.
PylonChatView(config: config, user: user, controller: _pylon,
  onReady: _pylon.hideChatBubble),
...
ListTile(
  leading: const Icon(Icons.support_agent),
  title: const Text('Contact support'),
  onTap: _pylon.openChat,
)
```

## Touch pass-through

The widget covers the whole screen but is mostly empty, so it has to be selective about which touches it takes. It works like this:

1. The web view reports where its interactive elements are — the bubble, and any popup survey or message — whenever they move or change visibility.
2. Those bounds are forwarded to Dart, where a custom render object accepts pointers inside them and reports a miss everywhere else.
3. A miss means Flutter's hit test carries on to the widgets behind, so your app receives the touch normally.
4. While the chat window is open the widget takes everything, since it owns the screen.

The practical consequences:

- Put `PylonChatView` **last** in a `Stack`, over the content it should float above.
- Do not wrap it in anything that swallows pointers (`AbsorbPointer`, an opaque `GestureDetector`, a `Container` with a colour and an `onTap`).
- Set `passthroughTouches: false` only if you are giving the widget a small box of its own rather than laying it over your app. It makes the whole overlay opaque to pointers.
- Turn on `debugMode` in `PylonConfig` to see the tap regions drawn over the widget when a tap is not landing.

## Troubleshooting

### The bubble never appears

Check `onError` and your app ID. With `enableLogging: true` the widget's own console output goes to `logcat` / the Xcode console, tagged `PylonWidget` on Android.

### Taps on the bubble do nothing

Something above the widget is taking the pointer first. Make sure `PylonChatView` is the last child of its `Stack` and that nothing wraps it in an `AbsorbPointer` or opaque `GestureDetector`. Turn on `debugMode` to see where the SDK thinks the tap targets are.

### Taps behind the widget do nothing

The reverse: the overlay is claiming pointers it should not. Check that `passthroughTouches` is left at its default of `true`.

### The chat is squashed when the keyboard opens

The widget is inside a `Scaffold` that is also resizing for the keyboard. Move it to `MaterialApp.builder` as shown above, or set `resizeToAvoidBottomInset: false` on the `Scaffold` that holds it.

### Android: file attachments do nothing

The SDK launches the file picker through the hosting `Activity`. This works out of the box with the standard `FlutterActivity`; if you use a custom `Activity` that overrides `onActivityResult`, call `super.onActivityResult(...)` so the plugin sees the result.

### Android: `Unsupported class file major version`

Install Java 17:

```bash
brew install openjdk@17
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
```

## Architecture

This package wraps the same native iOS and Android SDKs that ship in this repository — it is a binding, not a reimplementation. `scripts/copy-native-sdks.sh` vendors them in:

```
../ios/PylonChat/PylonChat.swift            → ios/Classes/PylonChat/
../android/pylon/.../com/pylon/chatwidget/  → android/src/main/kotlin/com/pylon/chatwidget/
```

Re-run it after changing either native SDK.

```
┌─────────────────────────────────────────────────────────────┐
│ Flutter (Dart)                                              │
│ PylonChatView + PylonChatController                         │
│ - Hit testing against the reported element bounds           │
│ - Method channel per view                                   │
└───────────────────────┬─────────────────────────────────────┘
                        │ Platform view + method channel
┌───────────────────────▼─────────────────────────────────────┐
│ Plugin bridge (iOS: Swift, Android: Kotlin)                  │
│ - PylonChatPlatformView.swift / .kt                         │
│ - Creation params → native config                            │
│ - PylonChatListener → channel events                         │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│ Native SDK (PylonChat)                                      │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ WebView (Pylon Chat Widget)                             │ │
│ │ - Loads from widget.usepylon.com                        │ │
│ │ - JavaScript ↔ Native bridge                            │ │
│ │ - Keyboard handling, file picker, external links        │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

Android uses hybrid composition, so the real `WebView` is in the view hierarchy and text input, selection controls, and the keyboard behave normally.
